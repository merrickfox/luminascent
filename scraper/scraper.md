Designing a scraping system for many sites

Part 1:
- we're going to use tampermonkey, so we'll need a tamper monkey script
- this is a sophisticated system but with a unique approach
- conventional scraping systems simply cannot go off to new sites without something breaking or needing something bespoke to that site, this is the problem we need to solve
- our tamper monkey system will allow us to go to many sites, we define where data lives once for that host (against a schema), then it can go and fetch it from all the pages
- here is how I envisage it working:
- - We define a schema for our structured data, we're currently working in the candle space but this system should be flexible for future projects, so there is a json file somewhere in the folder that tells the system we're interested in things like `productName`, `price`, `burnTime`, `notes` some of these there might be multiple of like notes, there is a full data schema in this project etc etc
- - In my browser I navigate to a product browse page, the system should have a menu overlay system it can render to, when on browse pages or mode it should try and find groupings of urls that are repeated, because this is how websites work, eg ul and li, it should pick up groups like top nav, footer links but also because all sites render products in a repeating way it should also pick out products, it lists these groups out in the menu and when I hover over one in the menu it highlights them all on the page so as the user I can verify this is the right group, then selecting it locks it in as the "products" and how products work for that host, it should store this (more on that later) and should be smart about javascript clickables vs pure urls etc
- - with the products blueprint stored I can now go to a product page and get into product mode, this should allow me to highlight text or elements in the page, once highlighted or selected a context menu should pop up where I can tag it as say `price`, the system should store this as the blueprint for where price is on all product pages, I can go though and tag up the entire page and lock it in, it should be smart about being able to find these elements on other pages, we can't just use class for example, many sites use react with random class names, we need to be resiliant about locking down where in the DOM this element truly is, we should assume all pages are similar but there could be some differences in the DOM eg a product that is on sale would have some new elements to display this, it should store this data
- - the system should be smart about when the page has finished rendering everything
- - it should also grab all images, it should re-render them in a menu where I can select the ones I want, in order too, so click on the first one and its tagged as 1, so on, clicking again untags it. Again the system needs to not only remember where these are in the DOM but store my preferences for extraction later
- - with the browse page, product page and images all spec'ed out we can now go back to browse and click a scrape button/extract mode, this opens all the products in new tabs and finds the elements and stores them against it's tag in the schema in a file (more on that later)
- storage and config, in this scraper folder we should also run a simple server that tampermonkey can talk to, this is how tamper monkey can write files locally, for each host where in the menu (start state) we click configure for scraping, it then creates a folder in /scraper/sites eg aerin_com, there will be a config and schema json it can request too from this server which will pull from a local json file, in eg aerin_com it can store the users DOM specifications and how they map to the schema and it will pull from these on future visits and when new tabs are spun up in scrape mode, for each product/tab opened up we create a new subfolder and we can maybe use the url partially as a valid folder name, then inside we can store a data.json that has the scraped data, eg "price": "£455.00", sometimes this data will have random or unexpected characters or spaces in them but thats ok, we will sanitise in a later iteration.
- we should also have an images folder (inside the specific product folder) that actually sends through the images from the site to the server and into this folder if possible, as opposed to grabing a url and trying to redownload later
- notes
- - sometimes information might be part of other information, so imagine a page that has a description section and description is part of our schema, however in the description it also normally contains a sentence about the fragrance notes, then we should have a way to tag as `descroption` but some kind of "also contains", "sometimes contains" etc then add other tags like `notes`
- - put this system in /scraper
- - IMPORTANT!! remember this is just one site of 1000s do not put custom code in just for one site, we must fix things at a conceptual level while maintaining it working for sites it might already work for
